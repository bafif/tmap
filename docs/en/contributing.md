# How to work on TellMAP

[Español](../es/contribuir.md)

A short guide to contributing to the code. What the project is and how it's built: [the README](../../README.en.md)
and [the plan](plan.md). Encyclopedia format: [ESQUEMA.en.md](../../data/enciclopedia/ESQUEMA.en.md).

## Conventions

- Code, comments and commits in Spanish. Documentation and user-facing text in Rioplatense Spanish and in English
  (see [Languages](#languages)).
- The interface is built in code (`scripts/interfaz/`), not in editor scenes. Themes are palettes in `tema.gd`.
- There is no year 0: negative years are BC. Use `Fechas` (`scripts/nucleo/fechas.gd`) to display and add them.
- To anchor a Control that's already in the tree, use `set_anchors_and_offsets_preset()`: `set_anchors_preset()`
  keeps the rectangle and leaves controls with zero size.
- `data/mapa/` is generated by `tools/pipeline/` (Python): don't edit it by hand, except `nombres_es.json` and
  `correcciones.json`, which are hand-made revisions. The encyclopedia is edited with the app's editor or by hand,
  validated with `python3 tools/enciclopedia/validar.py`, and anything uncertain gets flagged instead of made up.
- Everything the encyclopedia editor writes goes through `Edicion` (`scripts/nucleo/edicion.gd`): it preserves the
  JSON formatting and writes nothing while the interface walkthrough is running (`Estado.sin_escribir`).
- A new class with `class_name` doesn't require opening the editor: on startup, the app imports the project by itself
  if the class still needs registering (`scripts/nucleo/arranque.gd`).
- Before using a Godot API that isn't already in the code, check its signature with `tools/godot/tmap.py doc`.

## Testing and seeing your changes

- `tools/godot/tmap.py revisar`: compiles all the scripts.
- `tools/godot/tmap.py prueba`: the full automated test.
- `tools/godot/tmap.py lanzar`: opens the app with the bridge (without a display it uses `cage`). Then you use
  `anio`, `ir`, `seleccionar`, `pestana`, `captura`, `eval`, `errores`, `shader`, `recargar`, `clic` and the other
  commands (`ayuda`). When you're done, `cerrar`.
- With the editor open: `tools/godot/tmap.py --proyecto <editor folder> --a editor estado|escanear|jugar|abrir`.
- After every test, read `tools/godot/tmap.py registros --errores`: it has to end with "ningún nodo suelto
  sin liberar".
- Bridge details: [tools/godot/README.en.md](../../tools/godot/README.en.md).
- If you touch anything about how things are drawn: `tools/captura.sh x.png --comprobar_dibujo` (exits with 1 if the
  screenshot came out nearly flat), and the same with OpenGL, which is the macOS renderer:
  `GODOT_ARGS="--rendering-method gl_compatibility" tools/captura.sh x.png --comprobar_dibujo`. The renderer chosen
  in Settings is stored in `user://motor.cfg` (`scripts/nucleo/motor.gd`).
- From source, `user://` is `TellMAP-codigo` in the user's data folder (`~/.local/share/` on Linux), not the installed
  TellMAP's (`godot/app_userdata/TellMAP`): tests don't touch its settings or its data (`project.godot`, with the
  `editor` tag).
- If you touch the updater (`scripts/nucleo/actualizador.gd`, `datos.gd`) or how data is read:
  `python3 tools/actualizacion/probar.py`, and with an exported executable, `--ejecutable <path>`
  ([updates](updates.md)). Everything that reads `data/` goes through `Datos.ruta()`.

## Languages

- The app comes up in Spanish or English depending on the computer's language (`scripts/nucleo/idioma.gd`), and it
  can be changed in Settings or on the welcome screen; what the person picks wins over the detection.
  `--idioma=es|en` pins it for tests and screenshots.
- Every interface text is written in Spanish inside `tr()` (or `Idioma.t()` in static functions), and its English goes
  in `traducciones/en.po`. `python3 tools/traduccion/interfaz.py actualizar` adds new texts to the catalog, and
  `revisar` (it runs in CI) fails if one is missing, if the placeholders don't match, or if a text is assigned by hand
  outside `tr()`. Logs (`print`, `push_error`) stay in Spanish.
- The encyclopedia is translated separately, in one layer per package in `data/enciclopedia/traducciones/en/`
  ([the schema](../../data/enciclopedia/ESQUEMA.en.md#translations)), with `tools/traduccion/enciclopedia.py`:
  `estado` counts what's translated, missing and stale, `extraer` pulls out what's pending in batches for translation,
  and `aplicar` writes it into the layer. `tools/traduccion/probar.py` tests the round trip.
- The automated test runs in both languages: `tools/godot/tmap.py prueba` and `tools/godot/tmap.py prueba --idioma
  en`.
- The project page (`docs/index.html`) has the Spanish in the HTML and the English in its `EN` dictionary.
- Every document has its pair in the other language: `docs/es/` and `docs/en/`, and elsewhere `X.md` and `X.en.md`,
  with a link to the other one at the very top. `python3 tools/traduccion/documentos.py` (it runs in CI) fails if a
  document is missing its pair or if a relative link points to a file that doesn't exist. If you change one, change
  the other in the same commit.

## Progress

- Anything still pending goes under "To do" in [PROGRESO.en.md](../../PROGRESO.en.md), in its block and in priority
  order, with a bold title: `tools/github/organizar.py` creates one issue per item and recognizes it by that title, so
  it isn't changed. The Spanish `PROGRESO.md` is the one the script reads.
- Finished items leave "To do". If it's a milestone, it goes under "Done", in the version that ships it (or under
  "The encyclopedia" if it's content): what was decided and why, in one or two sentences, in the present tense and
  without a date or an account of how it was done.

## Git

- Changes are proposed with a pull request, using [its template](../../.github/pull_request_template.md).
- Screenshots for review go in a temporary folder, not the repo. The README ones go in `docs/assets/`.
